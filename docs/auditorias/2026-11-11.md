## Detalhamento dos Achados

### 1. Endpoints de geocodificação sem autenticação Firebase (`geocode` e `reverseGeocode`)

- **Severidade:** MÉDIO
- **Arquivo afetado:** `functions/src/geo/geocode.ts`
- **Comportamento vulnerável:** As Cloud Functions HTTP `geocode` e `reverseGeocode` continuam públicas e não exigem cabeçalho `Authorization: Bearer <idToken>` de um usuário autenticado no Firebase.
- **Impacto possível:** Requisições HTTP externas podem utilizar estas funções como proxy público para consultar a API do Google Maps Geocoding, consumindo a cota do projeto e incorrendo em custos vinculados ao segredo `GOOGLE_GEOCODING_KEY`.
- **Mitigação existente:** A função limita chamadas por IP a 40 requisições diárias (`limitePorIp.ts`), com hashing do IP e data, o que reduz o abuso em larga escala por bots simples.
- **Correção recomendada:** Adicionar verificação de Firebase ID Token quando o usuário já estiver autenticado (ex.: telas logadas) ou aplicar App Check quando a aplicação for publicada na Play Store (registrado em `memory-security.md` como pendência pós-publicação).
- **Cabe teste de regressão:** Sim. Testes em `functions/src/geo/limitePorIp.spec.ts` já cobrem a trava de limite de requisições.

## Verificação das Demais Superfícies de Segurança

### A. Credenciais e Histórico do Git

- **Status:** **CONFORME (BAIXO / Sem achados)**
- **Análise:** Varredura estática de padrões de chaves e segredos em todo o repositório confirma ausência de credenciais expostas. As chaves sensíveis (`ASAAS_API_KEY`, `ASAAS_WEBHOOK_TOKEN`, `GOOGLE_GEOCODING_KEY`) utilizam o Firebase Secret Manager (`defineSecret`).

### B. Logs e Proteção de Dados Sensíveis (PII)

- **Status:** **CONFORME (BAIXO / Sem achados)**
- **Análise:** Nenhum `console.log` vazando dados de autenticação, senhas, telefones ou e-mails foi identificado. No novo fluxo `deleteAccount.ts`, o logger registra apenas o sumário estatístico (`loja=sim/nao agendamentos=X`), suprimindo intencionalmente o `uid` e e-mail do usuário excluído.

### C. Regras do Firestore e Storage

- **Status:** **CONFORME (BAIXO / Sem achados)**
- **Análise:** As coleções sensíveis continuam devidamente blindadas:
  - `shops/{shopId}` restrita a usuários logados para leitura; criação com validação de trial (`trialDeNascimentoValido`); update protegido contra modificação de campos de cobrança (`camposDeCobranca()`).
  - `shopBilling/{shopId}` bloqueada para leitura e escrita por clientes (`allow read, write: if false`).
  - `users/{userId}` impede alteração de `role` pelo cliente.
  - `payments/{paymentId}` leitura permitida apenas ao dono do estabelecimento (`isShopOwner`).
  - `storage.rules` limita uploads à árvore `users/{uid}/` com tipo `image/*` e tamanho máximo de 5 MB.

### D. Webhooks e Pagamentos (Asaas)

- **Status:** **CONFORME (BAIXO / Sem achados)**
- **Análise:** A função `asaasWebhook` compara o token secreto usando `crypto.timingSafeEqual` para mitigar ataques de temporização. O aplicativo cliente não possui capacidade de atualizar ou aprovar assinaturas; todo estado financeiro é manipulado por Cloud Functions ou transações do Firestore no backend.

### E. Escalação de Papel (`customer` virando `owner`)

- **Status:** **CONFORME (BAIXO / Sem achados)**
- **Análise:** O campo `role` em `users/{userId}` permanece imutável via Firestore Rules após a criação da conta (`!request.resource.data.diff(resource.data).affectedKeys().hasAny(['role'])`).

### F. Travessia Entre Tenants (Isolamento Multi-Tenant)

- **Status:** **CONFORME (BAIXO / Sem achados)**
- **Análise:** Toda a modelagem de dados de clientes, agendamentos e serviços reside sob o caminho `shops/{shopId}/` com checagem rigorosa de `isShopOwner`. No módulo `shopOwnerGuard.ts`, a validação do formato do `shopId` (`/^[A-Za-z0-9_-]{1,128}$/`) impede traversals de caminho em subcoleções.

### G. Validação de Entrada

- **Status:** **CONFORME (BAIXO / Sem achados)**
- **Análise:** Entradas de formulários no app são validadas por `validation.utils.ts` e `cep.utils.ts`. Nas Cloud Functions, coordenadas e endereços são submetidos a `validarCoordenadas` e `validarEndereco`. O payload do webhook do Asaas possui guardas de tipagem em `asaasEvents.ts`.

### H. Armazenamento Local Inseguro

- **Status:** **CONFORME (BAIXO / Sem achados)**
- **Análise:** O `AsyncStorage` é empregado unicamente para guardar preferências de tema da interface (`Garage Dark`). Nenhum dado sensível (token, senha, documento pessoal) é armazenado sem criptografia no dispositivo móvel.

## Recomendação Geral

1. **Geocodificação e App Check:** Manter a proteção de limite por IP até o lançamento do app. Assim que a SHA-1 do Play App Signing estiver disponível, cadastrar no Console e habilitar o App Check nos endpoints públicos `geocode` e `reverseGeocode`.
2. **Exclusão de Conta (LGPD / Play Store):** O backend e a tela no app estão seguros e funcionais. Quando for disponibilizada a página web de suporte/privacidade do DetailGo, certificar-se de fornecer o link web de exclusão exigido pelas diretrizes do Google Play.
